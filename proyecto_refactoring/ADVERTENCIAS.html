ADVERTENCIAS CRITICAS DEL PLAN

PROBLEMA 1
Orden incorrecto: Seguridad debe ir ANTES de Testing
Las instrucciones originales ponen la Fase 5 (Seguridad) antes de la Fase 6 (Testing), pero esto es un error. Si mueves secrets a variables de entorno después de escribir tests, tendrás que reescribir todos los tests que usaban valores hardcodeados. Solución propuesta: invertir el orden.
PROBLEMA 2
Faltan prerequisitos críticos no mencionados
Las instrucciones no mencionan configuración básica del proyecto:
  • pyproject.toml o requirements.txt para dependencias nuevas (pytest, python-dotenv, mypy, ruff)
  • Archivo .env.example para documentar variables de entorno
  • Configuración de linter (ruff) y type checker (mypy)
Sin esto, cada fase deja el entorno roto y los tests no corren.
PROBLEMA 3
La Fase 3 es la más disruptiva y está subestimada
Separar api_movies.py y main.py en múltiples módulos es un cambio masivo que rompe dependencias en todo el proyecto. Las instrucciones la tratan como una fase más, pero es la que tiene mayor riesgo de romper funcionalidad existente.

Solución propuesta: dividir en 2 sub-ramas (3a y 3b) y mergear incrementalmente, no hacer un solo commit gigante.

Estas advertencias están documentadas para evitar errores comunes en el proceso de refactoring.
